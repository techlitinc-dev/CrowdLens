# Adapter Contract — Core API ↔ BettaFish ↔ MiroShark

**Version 0.1 · Source of truth for all service communication. Change this file FIRST, code SECOND.**

Transport: HTTP/JSON. Auth: shared internal token in header `X-Internal-Token` (value from `.env` as `INTERNAL_SERVICE_TOKEN`). All errors return:

```json
{ "error": { "code": "STRING_ENUM", "message": "human-readable", "retryable": true } }
```

Error codes: `INVALID_INPUT`, `UPSTREAM_FAILURE`, `NOT_FOUND`, `INSUFFICIENT_GROUNDING`, `RATE_LIMITED`, `INTERNAL`.

---

## 1. BettaFish adapter (real-data grounding)

Base URL: `http://bettafish:5001` (docker-compose service name).

### POST /collect
Start a collection job.

```json
{
  "job_id": "uuid, generated by core-api",
  "topic": "string, the decision question or subject",
  "keywords": ["array", "of", "strings"],
  "sources": ["reddit", "youtube"],
  "region": "global | in",
  "languages": ["en", "hi", "mr"],
  "max_items_per_source": 500,
  "time_window_days": 30
}
```
Response `202`: `{ "job_id": "uuid", "status": "queued" }`

### GET /collect/{job_id}/status
```json
{
  "job_id": "uuid",
  "status": "queued | running | done | failed",
  "progress": {
    "reddit":   { "collected": 320, "target": 500 },
    "youtube":  { "collected": 150, "target": 500 }
  },
  "error": null
}
```

### GET /collect/{job_id}/items?source=reddit&offset=0&limit=100
Paged, PII-stripped items:
```json
{
  "items": [{
    "item_id": "sha256 of platform+native_id",
    "source": "reddit",
    "url": "canonical post URL",
    "published_at": "ISO-8601",
    "text": "post/comment text",
    "language": "en",
    "metrics": { "score": 123, "comments": 45 },
    "region": "in | null"
  }],
  "total": 320
}
```

### POST /analyze/{job_id}
Runs baseline analysis (uses `report-model` via LiteLLM). Response `202`: `{ "report_id": "uuid", "status": "running" }`

### GET /analyze/{report_id}
```json
{
  "report_id": "uuid",
  "status": "running | done | failed",
  "summary": {
    "sentiment": { "positive": 0.41, "neutral": 0.33, "negative": 0.26 },
    "themes": [{ "label": "price concerns", "item_ids": ["..."], "claim": "Users say X", "citation_item_ids": ["item_id_1"] }],
    "key_entities": ["array of strings"]
  }
}
```
**Hard rule:** every `themes[].claim` MUST have ≥1 entry in `citation_item_ids`, and every cited id MUST exist in the collected items. Core-api verifies this and rejects the report with `INSUFFICIENT_GROUNDING` if violated.

## 2. Handoff payload (core-api → MiroShark)

Core-api's Handoff Transformer builds this from grounding output. Exact schema:

```json
{
  "simulation_id": "uuid, generated by core-api",
  "reality_seed_md": "markdown doc: facts, sentiment summary, verbatim quotes (with item_ids), key entities",
  "persona_panel": {
    "archetypes": [{
      "name": "string",
      "proportion": 0.25,
      "stance": "supportive | skeptical | neutral | hostile",
      "description": "who they are, what they care about",
      "language_samples": ["real quotes, item_id referenced"],
      "llm_model": "swarm-model"
    }]
  },
  "variants": [{
    "variant_id": "uuid",
    "label": "e.g. Price ₹399",
    "seed_patch_md": "markdown describing what changes vs baseline"
  }],
  "config": {
    "agent_count": 120,
    "rounds": 18,
    "early_stop_flat_rounds": 3,
    "model_alias": "swarm-model",
    "litellm_virtual_key": "sk-...per-project key..."
  }
}
```
Constraints core-api must enforce BEFORE sending: `agent_count` ≤ 150 · `rounds` ≤ 30 · `len(variants)` ≤ 3 (MVP) · proportions sum to 1.0 ± 0.01.

### POST /simulations
Body = handoff payload. Response `202`: `{ "simulation_id": "uuid", "run_ids": ["per-variant run id"] }`

### GET /simulations/{simulation_id}/status
```json
{
  "simulation_id": "uuid",
  "runs": [{
    "run_id": "uuid",
    "variant_id": "uuid",
    "ensemble_index": 0,
    "status": "running | done | failed | checkpointed",
    "current_round": 12,
    "total_rounds": 18,
    "early_stopped": false
  }]
}
```

### GET /simulations/{simulation_id}/results
```json
{
  "simulation_id": "uuid",
  "runs": [{
    "run_id": "uuid",
    "variant_id": "uuid",
    "final_sentiment": { "positive": 0.5, "neutral": 0.2, "negative": 0.3 },
    "stance_by_archetype": [{ "archetype": "name", "support": 0.6, "oppose": 0.3, "neutral": 0.1 }],
    "top_objections": [{ "theme": "string", "quote_refs": ["agent_id:round:post_id"] }],
    "narratives": [{ "label": "string", "momentum": "rising | flat | falling" }]
  }]
}
```
Every `quote_refs` entry must resolve to a simulated post in that run. Labeled simulated — never present as real.

### POST /simulations/{simulation_id}/ask
```json
{ "run_id": "uuid", "agent_id": "string", "question": "string" }
```
Response: `{ "answer": "string", "simulated": true, "run_id": "uuid", "round_context": [3, 7] }`

## 3. Ensemble & verdict rules (core-api side, fixed)

1. Run 3 ensemble runs per variant. Compute pairwise agreement on **winning direction** (support vs oppose majority) and **top-3 objection themes**.
2. Agreement = fraction of runs sharing the modal direction AND ≥2/3 overlap in top objection themes.
3. If agreement ≥ 0.8 → verdict allowed. If < 0.8 and runs < 7 → launch another run. If 7 runs without convergence → verdict = `NO_CONSENSUS` with divergence summary. **Never force a verdict.**
